# omp-codex-transfer

Продолжайте разговор из [Oh My Pi](https://github.com/can1357/oh-my-pi) в Codex с помощью команды `/codex-transfer`.
Расширение создаёт отдельную Codex-сессию из активной ветки разговора и показывает команду для её открытия.
Исходная OMP-сессия остаётся без изменений.

## Установка

Нужны установленные Oh My Pi и Codex CLI.
Команды `omp` и `codex` должны быть доступны в `PATH`.
Claude Code устанавливать не нужно.

```bash
git clone https://github.com/TiraelSedai/omp-codex-transfer.git
cd omp-codex-transfer
omp plugin link "$PWD"
```

Устанавливать зависимости проекта через `npm install` для использования расширения не нужно.
Не перемещайте и не удаляйте каталог после подключения: OMP загружает расширение из него.

В уже открытой сессии OMP выполните:

```text
/reload-plugins
```

Либо перезапустите OMP.
Если ещё не вошли в Codex, выполните в терминале `codex login`.

## Перенос разговора

1. Откройте нужную сессию и выберите нужную ветку в OMP.
2. Дождитесь завершения ответа агента и обработки очереди сообщений.
3. Выполните команду без аргументов:

   ```text
   /codex-transfer
   ```

4. Скопируйте выведенную команду в терминал.
   Она перейдёт в рабочий каталог и откроет созданную сессию:

   ```bash
   cd '/path/to/project' && codex resume '<thread-id>'
   ```

5. Напишите следующий запрос в Codex и продолжайте работу.

Имя новой сессии начинается с `[OMP]`.
Сам перенос не отправляет запрос к модели и не запускает выполнение задачи в Codex.

Каждый вызов `/codex-transfer` создаёт новую независимую копию.
Это не синхронизация: последующие сообщения в OMP не появятся в уже созданной Codex-сессии, и наоборот.

## Что переносится

- Сообщения пользователя и ответы ассистента из активной ветки, без соседних веток.
- История вызовов инструментов и их результатов как текст, без повторного выполнения.
- Сводки сжатия контекста и переключения веток.
- Изображения как локальные файлы с путями в разговоре.

Codex может сокращать длинные аргументы и результаты инструментов при импорте.
Если ему не хватает подробностей, попросите прочитать полный экспортированный JSONL: путь к нему добавляется в разговор и показывается после переноса.
Для просмотра изображения попросите Codex открыть указанный в разговоре файл.

Внутреннее reasoning и состояние провайдера не переносятся.
Субагенты OMP не становятся работающими субагентами Codex, а ссылки `agent://` и `local://` не становятся ресурсами Codex.
Расширение переносит историю, а не настройки OMP, инструменты или файлы проекта.

## Где хранятся данные

После переноса остаётся каталог:

```text
~/.claude/projects/omp-transfer-<unique-id>/
  session.jsonl
  image-1.png
  ...
```

Каталог `.claude/projects` нужен импортеру Codex; установленный Claude Code для этого не требуется.
JSONL содержит экспортируемую историю, включая полные аргументы и результаты инструментов.
Изображения сохраняются рядом с ним.
Каталог доступен только владельцу, файлы создаются с правами `0600`.

Снимки могут содержать код, личные данные и секреты из разговора.
Не публикуйте их и не добавляйте в Git.
Автоматической очистки нет: удаляйте конкретный каталог снимка вручную, когда его оригиналы больше не нужны.
После удаления Codex потеряет доступ к этим изображениям и полным результатам инструментов, но импортированная история останется в его сессии.

Новая сессия сохраняется в хранилище Codex, выбранном через `CODEX_HOME`, либо в стандартном `~/.codex`.
При продолжении используйте то же значение `CODEX_HOME`, если задавали его для OMP.

## Продолжение с телефона

Расширение создаёт локальную Codex-сессию, но не настраивает удалённый доступ и не копирует проект на телефон.
Для работы с телефона отдельно настройте Codex Remote на компьютере, где находятся проект и созданная сессия.

## Если перенос не получился

- **OMP ещё работает или есть очередь сообщений:** дождитесь завершения и повторите `/codex-transfer`.
- **Пустая ветка:** выберите разговор с сообщениями.
- **Команда `codex` не найдена:** установите Codex CLI и убедитесь, что он доступен в окружении, из которого запущен OMP.
- **Codex не поддерживает API импорта:** обновите Codex CLI.
- **Ошибка после создания снимка:** команда покажет ошибку и путь к сохранённому JSONL.
  Снимок остаётся доступен для разбора проблемы; повторный вызов создаст новый снимок.

## Обновление

В каталоге расширения выполните:

```bash
git pull --ff-only
```

Затем выполните `/reload-plugins` в OMP или перезапустите его.
